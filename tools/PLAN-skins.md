# 着せ替えごとにルールを変える計画

いまの着せ替えは見た目だけ(冬だけ動きがわずかに違うが、ルールは同じ)。
これを「着せ替えごとに別のルール・別のステージ」に変える。

## 進める順番

土台を先に作り、ルールの差分が小さいものから順に乗せる。
1つ仕上げるたびに公開して、確かめてから次へ進む。

| 順 | 名前 | ルール | なぜこの順か |
|---|---|---|---|
| 0 | **土台** | — | ルールを差し替えられるようにする。全部の前提 |
| 1 | **夏** 🦀 | 水パネル。カニは通れるが、ダンボールは通れない | ルールの差分が一番小さい。土台が正しいかを確かめる |
| 2 | **リス** 🐿️ | 置き場は穴。ドングリを埋めるまで通れない、埋めたら通れる | 差分が小さく、状態も増えない |
| 3 | **冬** ⛄ | 氷は壁か氷にぶつかるまで滑る | 押した先が変わるだけ。状態はむしろ減る |
| 4 | **ふつう2** 🐣 | ダンボールと置き場に番号。番号が一致しないとダメ | **既存の盤をそのまま使える**。番号を振って解き直すだけ |
| 5 | **フンコロガシ** 🪲 | 押すたびにウンコが90度回る。正しい向きでないとクリアにならない | 荷物ごとに向き(4通り)が付き、状態が数十倍になる |
| 6 | **春** 🐝 | ミツバチ2匹を交互に動かす | 人が2人ぶん。状態が大きく増える |
| 7 | **蟻** 🐜 | 同僚の蟻が、こちらが動かすたびに規則どおりに動かす | 一番重い。規則を決めないと着手できない |

## 各段でやること(1つあたり)

1. ルールを engine に足す(局面の遷移と、解けた判定)
2. そのルールで解ける探索を用意する(最短手数を出す・検算する)
3. 面を作る … **ごく簡単なものから、かなり難しいものまで20面**
4. チュートリアルを数面、先頭に置く … ふつうとの違いが1面で1つ分かる形にする
5. 行き来できるようにする(着せ替えを選ぶ画面)
6. 全面を検証する(解ける / 記録した最短手数どおりか)

## 土台でやること(第0段)

- `pushesFrom` が唯一のルール定義箇所なので、ここを着せ替えごとに差し替える形にする
- 面は着せ替えごとに別のファイルへ(`warehouse/packs/<名前>.json`)。
  ふつうの1000面はそのまま。他の着せ替えは自分のぶんだけを読む
- クリア記録も着せ替えごとに分ける(いまの `warehouse-progress` は、ふつう用として残す)
- チュートリアル面に一言の説明を付けられるようにする

## 決めてもらう必要があること

着手前に要るもの。**7(蟻)は規則が決まらないと作れない。**

### 蟻の規則
「一定の規則で」の中身。たとえば:
- どの蟻が動くか … 全部 / 一番近い1匹
- 何を押すか … その蟻から一番近いダンボール
- どこへ押すか … 一番近い置き場に近づく向き / こちらが押したのと同じ向き
- 押せないときは … 動かない / 空いている向きへ押す

### フンコロガシの向き
- 90度回る向きは、いつも同じ(右回り)か、押した向きで決まるか
- 「正しい向き」は置き場ごとに決まっているのか、全部同じか
- 遊ぶ人にどう見せるか(ウンコの絵に印を付ける必要がある)

### 春の交代
- 「交互に動かす」は、1歩ごとの交代か、1回押すごとの交代か
- 動かす番でないミツバチは、もう片方の壁になるか、すり抜けられるか

## 触らないもの

- ふつうの1000面。いま重複の差し替えを進めている最中で、そちらは別作業
- 第1〜300面の中身
