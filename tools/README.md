# 面を足す手順

いま **1000面**。全1000面が検証済み（解けて、記録した最短手数も一致）。

## 動かしてよい範囲

**第400面までは固定**（2026-08-17、本人の指示）。線は `tools/frozen.js` にあり、
並べ替えの道具はここを読んで、この番号以下には手を出さないこと。
線を動かしてよいのは本人が言ったときだけ。

第401面以降は並べ替えてよい。ただし面の**中身**は、序盤の簡単な面も含めて触らない。
簡単な面が混ざっていること自体が次の面のひっかけになる。
（理由は `moderation/README.md` の「全部をこの条件に通してはいけない」）

新しい面は末尾に足す。

## 1. 作る

```sh
sh tools/gen-hard-parallel.sh 10 600 /tmp/hard      # 1本10面・600秒 × 4並列
```

`/tmp/hard/all.json` に、重複を除いた候補が手数の多い順で出る。
1面あたり3〜4秒。10面ほしければ5分みておけばよい。
やさしめの面がほしいときは `tools/gen-thinky.js`（同じ4つの入口、手数の下限が低い）。

出てきた表の見かた:

| 列 | 意味 | 目安 |
|---|---|---|
| 経路 | まっすぐ運ばせてもらえない割合 | 大きいほど良い |
| 囮 | 置き場に近づく押し手のうち、正解でないものの割合 | 大きいほど良い |
| 強制 | 最短を保つ手が1本しかない局面の割合 | 単独では意味がない |
| 型 | 思考 / 順番 / 囮 / 経路 のどれで通ったか | 偏っていないか見る |

## 2. 足す

```sh
node tools/append-hard.js /tmp/hard/all.json
```

- 1面ずつ**解き直して検算**する（記録した手数どおりに解けるか）
- 既存と同じ盤は落とす
- 末尾に**やさしい順**で並べ、`orig` を振り直す

数を絞りたいときは、`all.json` を手で削ってから渡す。

## 3. 確かめる

```sh
node tools/verify-levels.js      # 全件。ID重複・盤面の成立・最短手数
node tools/build-preview.js      # /home/user/warehouse-preview.html
```

`verify-levels.js` は生成器とは**別経路の前向きBFS**で解き直す。全600面で数分かかる。

## 4. 出す

```sh
git add -A && git commit -m "…"
git push -u origin claude/sokoban-auto-generation-vrgili
git checkout main && git merge --ff-only claude/sokoban-auto-generation-vrgili
git push origin main && git checkout claude/sokoban-auto-generation-vrgili
```

`main` に入ると GitHub Pages に出る（反映は1分ほど、キャッシュは10分）。

## やってはいけないこと

- **並べ替え**。`tools/append-sorted.js` は指定した面から末尾までを手数順に並べ直す。
  もう使わない。面番号がずれると、クリア履歴の自己ベストは id で持っているので
  記録自体は残るが、遊ぶ側の「第N面」の意味が変わる
- **既存の面の差し替え**。`replace-slots.js` `regen-slot.js` も同様に、いまは使わない
- **指標で既存の面をふるいにかけること**。指標は新規生成にだけ使う

## 面白さの基準（`tools/gen-hard.js` の定数）

104面のラベルから決めた。入口は4つで、どれか1つ通ればよい。

| 定数 | 値 | 意味 |
|---|---|---|
| `MIN_PUSH` | 28 | これ未満は採らない |
| `MIN_LATE_R` | 0.25 | 終盤の回り込み ÷ 床。**必ず床の数で割る** |
| `A_MANO` / `A_DECOY` | 0.35 / 0.30 | 思考型（遠回りさせられ、偽の手がある） |
| `B_ACCESS` | 0.43 | 順番型（荷物は動くのに自機が届かなくなる。囮0.25以上と併用） |
| `C_DECOY` / `D_MANO` | 0.40 / 0.50 | 片方だけ突出していれば、もう片方は要らない |
| `MAX_FORCED` / `MIN_SPREAD` | 0.35 / 10 | 一本道**かつ**選択肢も少ない面だけ弾く |

共通で必ず弾くもの:

- **素直に解ける**（置き場に近づいて見える手だけで解けてしまう）… ラベル16面中15面が✕
- **終盤の回り込みが床の0.25未満**

歩数・手数・局面数のような「量」をそのまま条件にすると、実質「小さい盤を全部落とす」
フィルタになる。必ず盤の大きさで割ってから使うこと。

## 新しい面を判断したいとき

`?mod=1` で遊びながら ★✕ を付け、「★✕を書き出す」で JSON を落として
`tools/moderation/roundN.json` に置く。ラウンドごとの取り方と、そこから分かったことは
`moderation/README.md` に書いてある。本人が名前を挙げて褒めた面は `favourites.json`。

★のデータが少ないのがこの分析の弱点で、「何が悪い面か」は当たるが
「何が良い面か」を区別する材料が乏しい。褒めた面は必ず `favourites.json` に足すこと。
