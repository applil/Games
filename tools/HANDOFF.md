## 2. 作り

### 本体は1組しかない

```
lib/game.js    ゲーム本体。画面の組み立てもこの中（テンプレート文字列）
lib/game.css   見た目。着せ替えの色もここ
warehouse/engine.js   ふつうのルールの探索（詰み表・ヒント用）
warehouse/rules.js    着せ替えごとのルール。探索と道具はこれを使う
```

入口（`warehouse/index.html` など）は**27行の殻**で、中身はこれだけ。

```html
<script>window.GAME={pack:'mark', asset:'../warehouse/'};</script>
<script src="../warehouse/engine.js"></script>
<script src="../lib/game.js"></script>
```

**入口を増やすときは `tools/pages.js` の `GAMES` に1行足して `node tools/pages.js` を回す。**
手で `index.html` を書かないこと。メニュー（リポジトリ直下の `index.html`）にも
1件足す（`class="game <名前> rule-only"`。`rule-only` はデバッグ表示のときだけ出る印）。
`lib/game.js` の `PACKS` にも1件足す（入口・絵・題・説明もここに書く。
デバッグの「ルールを選ぶ」一覧はこれを読む）。

### 盤の書き方（XSB に足したもの）

```
#壁  空白床  .置き場  $荷物  *置き場の上の荷物  @自機  +置き場の上の自機
~ 水      … 夏。自機は通れるが荷物は通れない
1〜9      … 印あわせ。印つきの荷物
a〜i      … 印あわせ。印つきの置き場（1がa、2がb…）
& 同僚の蟻 … 蟻
@ を複数  … 春（盤の左上からの順で1匹目・2匹目…）
```

印は 1,2,3… と続いていないといけない。抜けがあると読み込みで止まる。

### `rules.js` の約束

```
parse(board)   盤の文字列を、そのルールが要る形に開く
start(p)       最初の局面
moves(p, st)   その局面から進める先（押し手の一覧）
solved(p, st)  解けたか
key(st)        局面を見分ける鍵（同じ局面を二度見ないため）
```

**いちばん大事なこと** … ルールの中身は `rules.js`（探索・道具用）と
`lib/game.js`（画面用）の**2か所にある**。片方だけ直すと
「探索では解けるのに画面では解けない／手数が違う」という形で出る。
`build-pack` の検算は探索側しか見ないので、そこは通ってしまう。
**ルールを触ったら必ず両方を直し、`tools/play-check.js` を回すこと。**
このセッションだけで、これが原因のバグを3回踏んでいる
（蟻の同点の決め方・蟻の並べ直し・春の変数名）。

### 面のファイル

```
warehouse/levels.json               本編1000面
warehouse/packs/<名前>.json          遊ぶときに読む（build-pack が作る）
warehouse/packs/<名前>-tutorial.json 手で作る。生成器は触らない
warehouse/packs/<名前>-raw.json      生成器が書く。手では触らない
tools/stock/gen-*.json              生成器の途中経過（担当ごとに別ファイル）
```

`node tools/build-pack.js <名前>` が `-tutorial` と `-raw` をつないで `<名前>.json` を作り、
**そのとき全面を解き直して、記録した手数どおりか確かめる**。

## 3. 道具

```
node tools/pages.js                  入口ページを書き出す
node tools/build-pack.js <名前>       パックを組み立てる＋全面を検算
node tools/play-check.js <入口> <パック> <ルール>   画面から解けるかを全面ためす ★重要
node tools/verify-levels.js           本編1000面の検証（SHARDS/SHARD で分割可）
node tools/gen-variant.js <ルール> <数> <秒> <種> <出力>    面を作る
node tools/gen-marks.js <数> <出力>   印あわせを本編の盤から作る（種は使い切った）
node tools/thin-pack.js <名前> <上限>  同じ手数・同じ種類の面を間引く
node tools/mark-cross.js              印あわせで「入れ替え」を使う面かを見る
node tools/find-twins.js / swap-dups.js / frozen.js   本編の重複さがしと差し替え
```

`gen-variant.js` の環境変数:
`MIN_PUSH` `MAX_PUSH` `NBOX` `SIZE` `WATER` `DUP`
`MATTERS=0`（ふつうと同じ手数の面も残す。チュートリアル用）
`BEES=3`（春。ミツバチの数）

`gen-marks.js`: `MARK=all|part|few`

### 面を作るときの考え方

1. 乱数で盤を作る → そのルールで解く → 手数が範囲に入っているものだけ残す
2. **ふつうのルールで解いた答えと同じ手数なら捨てる**（そのルールの意味がない飾り）
3. 最短手順の押し手の集合が、既にある面と 0.7 以上重なったら捨てる

### 検証の流れ（省かないこと）

```
1. python3 -m http.server 8791 --bind 127.0.0.1   ← 先に立てる
2. node tools/build-pack.js <名前>                 ← 探索側の検算
3. node tools/play-check.js <入口> <パック> <ルール> ← 画面側の確認
```

`play-check.js` は探索が出した最短手順を、実際に画面の `move()` を叩いてなぞる。
蟻の同僚や春の相方は画面が自前で動かすので、食い違えばここで必ず出る。

## 4. ルールの決まり（本人が決めたもの。勝手に変えない）

### 夏 🦀 水
水のマスは自機だけ通れる。荷物は押し込めない。

### リス 🐿️ 穴
置き場は穴。ドングリを落として埋めるまで通れない。埋めたら床。埋めたものは動かせない。

### 冬 ⛄ 滑る氷
壁か別の氷にぶつかるまで滑る。押した本人はその場に留まる。
**止まるのはぶつかるからで、摩擦ではない** → 効き方は `linear`。減速させない。
距離が伸びるほど時間も伸ばす（距離の0.65乗、上限1.3秒）。

### 印あわせ 🐣
印つきの荷物は同じ印の置き場へ。印の無い荷物は印の無い置き場へ（**厳密一致**）。
一度「印の無いものは万能札」に変えたが、別の担当が厳密一致に戻している。いまは厳密一致。

### ころがし 🪲
押すたび時計回りに90度。全部が置き場に乗り、かつ向きが元に戻ってクリア。
**回るのと移るのは同時。** 移動は `left/top`、向きは `rotate` と分けてある
（CSS は `rotate` を `transform` より先に掛けるので、同じ要素で両方使うと
移動の向きまで回ってしまう）。

### 春 🐝 ミツバチ（2匹）
1回押すごとに、**盤の左上からの順ぐり**で交代。番でない子は全員が壁。
押さずに歩くだけでは交代しない。押した子は荷物のいた場所に残る。
2匹のときは「どちらが番か」を局面の見分けに入れない（2匹に区別がないため）。

### 蟻 🐜（2026-08-24〜25 に何度も詰めた。いまの形）

あなたが1回押すたびに、同僚が**盤の左上に近い順**に1匹ずつ動く。
前の蟻が動いた結果を次の蟻が見る。1匹ぶんの手順:

1. **取り付いていなければ、一番近い荷物に取り付く**（押す位置までの歩数）
2. **荷物に接するまでの道は、曲がる回数がいちばん少ないもの**を選ぶ。
   **押す場所に立ったら、その場で向きを変えて押す**（着いたときの向きには縛られない）。
   2026-08-28 に本人が決めた。それまでは「接したときに進んでいた向きが押す向き」で、
   そのせいで「押す場所まで来ているのに、いったん脇へ出て入り直す」歩き方をしていた
   （第2面で実際に出た）。この変更で37面→32面
   （手数が変わった15面は記録を直し、解けなくなった3面と、
   ふつうと同じ手数になった2面は捨てた）
3. **1手につき1マス押す**。押す位置までは何マスでも歩く（手数には数えない）
4. **一度押しはじめたら、その荷物に執着する**（近くに別の荷物が来ても乗り換えない）
5. **その向きに押せなくなったら回り込む**。まず左右（直角）で曲がりの少ないほう、
   だめなら反対側。それも無理ならその荷物を手放す
6. **主人公が直前に押した荷物には触らない**
7. **置き場に収まった荷物には触らない**（そろえたそばから崩さない。
   これでクリア後に動き続けることも無くなる）
8. **やることが無くなったら止まっている**

同点の決め方（こちらで決めたもの。違ったら直す）:
**曲がりの少なさ → 歩く距離の短さ → 上・下・左・右の順**。
荷物が同じ歩数で並んだら盤の左上に近いほう。
1つの荷物に取り付けるのは1匹だけ（左上の蟻から先に決める）。

**外した案**（本人の指示で取り消したもの。復活させないこと）:
蟻の向きを示す矢印、押す先の茶色い枠、蟻が1手に1マスずつ歩く形。

### 色と形（2026-08-30 に本人が決定。色弱の知人の指摘から）

**置き場は色だけで示していた。それをやめ、色と形の両方で示す。**

- **全ルール**: タイルの外枠のすぐ内側に輪郭（1.5px）。
  空き=破線 / 収まった=実線 / 印ちがい=点線。`.cell.goal::before` ほか。
  `::after` は水たまり・穴が使っているので `::before` を使うこと
- **倉庫パズル・印あわせ・ころがし・すべる氷・蟻**: 置き場=橙 `#f0b76a`、
  収まった=青 `#8fb9dc`。橙と青は、どの色覚でも色みの向きが入れ替わらない
- **ミツバチ**: 置き場は桃色のまま少し濃く `#eda3c4`、壁の緑も少し濃く `#7a9c4a`、
  収まったは**濃い**青 `#4a7fbb`。薄い青だとP型で桃色が沈んで青に寄る
- **カニと水**: 置き場の橙はそのまま、収まったは**濃い**青 `#4a7fbb`。
  薄い青だと赤緑の型で水（青緑）とほぼ同じ色になる（実測 D型で ΔE1.5）
- **リス**: 置き場は穴なので色は変えない。埋めた穴だけ `--shut:#e8dfb9` に。
  **グラデは付けない**（一度ふちにグラデを入れたが、穴が残って見えて変だった）
- **印あわせ**: 置き場の印も**黒**（`--ink`）。前は置き場の色で、薄い地に同系の字で読めなかった

全ルール・全型（P/D/T）で、いちばん近い組み合わせでも ΔE17 以上あることを確認済み。
見比べる見本と、実際に置き場を探して試せる仕掛けを作ってある（この会話の Artifact）。

## 6. 編集モード（デバッグ表示から入る）

8ルールすべてで、盤を編集して「解けるか確かめる」ができる。
確かめは `rules.js` でそのルールのまま解く。道具はルールごとに出し分け:

```
共通       壁 / 床 / 置き場 / 荷物 / 自機
夏         ＋水
印あわせ   ＋荷物A〜C・置き場A〜C
春         ＋ミツバチを足す（何匹でも）
蟻         ＋同僚のアリ
```

`boardToXSB()` が駒を1つでも書き落とすと、**別の盤を確かめてしまう**。
蟻の `&` と春の2匹目が抜けていて、実際に嘘の答えを出していた（直してある）。
道具を足したら、書き出し→読み直しで駒が落ちないことを必ず確かめること。

## 7. この環境の落とし穴（何度も踏んだ）

- **作業ディレクトリが何度も古いコミット（`43fbe5c`）まで巻き戻る。**
  このセッションで10回以上起きた。コミットしていない変更は消える。
  **作業は小さく切って、その都度コミットしてプッシュすること。**
  復帰は `git fetch origin <branch> && git checkout -B <branch> origin/<branch>`
  - **巻き戻ったあとフックが「未プッシュのコミットがある」と言うことがある。
    それは古いコミットなので、押してはいけない**（公開中のサイトが巻き戻る）。
    ローカルが origin より後ろかどうかを必ず確かめる
- **`/tmp` も消える。** 使い捨てのスクリプトを置くと消える。
  何度も使うものは `tools/` に置くこと（`play-check.js` はそれで移した）
- **同時に何本も走らせるときは、控えを担当ごとに別ファイルにする**
- **`pkill -f "..."` は自分の shell も殺す。** PID を調べて `kill <PID>` にする
- **playwright は `/opt/node22/lib/node_modules/playwright`** にある。
  Chromium は `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`。
  `playwright install` は不要
- `element.screenshot()` は動きが止まるまで待つ。アニメーションの途中を撮るなら
  `page.screenshot({clip})` か `animationPlayState='paused'` で止めてから
