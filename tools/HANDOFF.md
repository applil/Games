## 1. これは何か

- 公開先 … `https://applil.github.io/Games/`
- リポジトリ … `applil/Games`
- 作業ブランチ … `claude/sokoban-auto-generation-vrgili`
- デプロイ … ブランチに push したあと `git push origin <branch>:main`。

## 2. 作り

### 本体は1組しかない

```
lib/game.js    (2800行)  ゲーム本体。画面の組み立てもこの中（テンプレート文字列）
lib/game.css   (580行)   見た目。着せ替えの色もここ
warehouse/engine.js      ふつうのルールの探索（詰み表・ヒント用）
warehouse/rules.js       着せ替えごとのルール。探索と道具はこれを使う
```

入口（`warehouse/index.html` など）は**27行の殻**で、中身はこれだけ。

```html
<script>window.GAME={pack:'mark', asset:'../warehouse/'};</script>
<script src="../warehouse/engine.js"></script>
<script src="../lib/game.js"></script>
```

- `pack` … `lib/game.js` の `PACKS` の鍵。`null` なら本編
- `asset` … 絵や面のファイルの置き場（本編は `''`、ほかは `'../warehouse/'`）

**入口を増やすときは `tools/pages.js` の `GAMES` に1行足して `node tools/pages.js` を回す。**
手で `index.html` を書かないこと。メニュー（リポジトリ直下の `index.html`）にも
1件足す（`class="game <名前> rule-only"`。`rule-only` はデバッグ表示のときだけ出る印）。

### 盤の書き方（XSB に足したもの）

```
#壁  空白床  .置き場  $荷物  *置き場の上の荷物  @自機  +置き場の上の自機
~ 水      … 夏。自機は通れるが荷物は通れない
! 水の上の自機 … 編集で書き出すとき。@ だけだと足元の水が消える
1〜9      … 印あわせ。印つきの荷物
a〜i      … 印あわせ。印つきの置き場（1がa、2がb…）
& 同僚の蟻 … 蟻
@ が2つ    … 春（左上から1匹目・2匹目）
```

印は 1,2,3… と続いていないといけない。抜けがあると読み込みで止まる。

### `rules.js` の約束

どのルールも同じ形で答える。

```
parse(board)   盤の文字列を、そのルールが要る形に開く
start(p)       最初の局面
moves(p, st)   その局面から進める先（押し手の一覧）
solved(p, st)  解けたか
key(st)        局面を見分ける鍵（同じ局面を二度見ないため）
```

局面（`st`）の中身はルールごとに違ってよい。共通は `boxes` と `rep`（自機の区画の代表値）。

**大事** … ルールの中身は `rules.js`（探索・道具用）と `lib/game.js`（画面用）の
**2か所にある**。片方だけ直すと、画面で解けたのに記録と手数が合わない、という形で出る。
蟻で実際に食い違った（同じ距離・同じ向きのときにどの荷物を選ぶかが片方に無かった）。
**ルールを触ったら必ず両方を直し、下の「画面から解く検証」を回すこと。**

### 面のファイル

```
warehouse/levels.json          本編1000面
warehouse/packs/<名前>.json         遊ぶときに読むもの（この道具が作る）
warehouse/packs/<名前>-tutorial.json 手で作る。生成器は触らない
warehouse/packs/<名前>-raw.json      生成器が書く。手では触らない
```

`node tools/build-pack.js <名前>` が `-tutorial` と `-raw` をつないで `<名前>.json` を作り、
**そのとき全面を解き直して、記録した手数どおりか確かめる**。

分けてあるのは、生成器がファイルを読み込んだまま持っていて、
同じファイルに手で書き足すと次の1面で上書きされて消えるため（実際に一度消えた）。

## 3. 道具（よく使うもの）

```
node tools/pages.js                入口ページを書き出す（GAMES に足してから回す）
node tools/build-pack.js <名前>     パックを組み立てる＋全面を検算
node tools/verify-levels.js         本編1000面の検証（SHARDS=4 SHARD=0..3 で分けられる）
node tools/gen-variant.js <ルール> <数> <秒> <種> <出力>   ルール違いの面を作る
node tools/gen-marks.js <数> <出力>  印あわせの面を、本編の盤から作る
node tools/thin-pack.js <名前> <上限> 同じ手数・同じ種類の面を間引く
node tools/find-twins.js            同じ部屋の面を探す（本編の重複さがし）
node tools/swap-dups.js             重複を差し替える
node tools/frozen.js                並べ替えてよい範囲の線（第430面まで固定）
```

`gen-variant.js` の環境変数 … `MIN_PUSH` `MAX_PUSH` `NBOX` `SIZE` `WATER` `DUP`
`MATTERS=0`（ふつうと同じ手数の面も残す。チュートリアル用）

`gen-marks.js` の環境変数 … `MARK=all|part|few`（印を全部／一部だけ／少なめに付ける）

### 面を作るときの考え方

1. 乱数で盤を作る → そのルールで解く → 手数が範囲に入っているものだけ残す
2. **ふつうのルールで解いた答えと同じ手数なら捨てる**（そのルールの意味がない飾りだから）
3. 最短手順の「どの荷物をどこへ押したか」の集合が、既にある面と 0.7 以上重なったら捨てる

## 4. 検証のしかた（これを省かないこと）

面が「解ける」ことを探索で確かめるだけでは足りない。
**画面の操作だけで、記録どおりの手数で解けるか**を必ず確かめる。
探索（`rules.js`）と画面（`lib/game.js`）でルールの実装が別なので、ここでしか食い違いが出ない。

やり方（実際に使っている形）:

1. ローカルに静的サーバを立てる … `python3 -m http.server 8791 --bind 127.0.0.1`
2. node 側で `rules.js` を使って最短手順（押し手の列）を出す
3. Playwright で入口を開き、各面について
   「押す位置まで歩く経路を、画面と同じ条件（壁・荷物・相方・蟻）で探して `move()` を並べる」
4. 最後に `finished` が立ち、`pushCount` が記録と一致するかを見る

Chromium は `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` にある
（`playwright install` は不要）。

見た目を確かめるときは、`element.screenshot()` は動きが止まるまで待つので、
アニメーションの途中を撮りたければ `page.screenshot({clip})` を使うか、
`animationPlayState='paused'` で止めてから撮る。

### 着せ替えごとのルール（本人が決めた形）

- 夏 … 水は自機だけ通れる。置き場の色は水と紛れないものにする
- リス … 置き場は穴。埋めるまで通れない。埋めたドングリは二度と動かせない
- 冬 … 氷は壁か別の氷にぶつかるまで滑る。押した本人はその場に留まる
- 印あわせ … **A は A の置き場、B は B の置き場へ。印の無い荷物は印の無い置き場へ。**
  印の無いものは万能札にしない。印なしは稀（チュートリアルで1〜2面、100面までに5面くらい。それ以降は徐々に増やす）
- ころがし … 押すたび時計回りに90度。全部が置き場に乗り、かつ向きが元に戻ってクリア
- 春 … 1回押すごとに交代。番でないミツバチは壁。押さずに歩くだけでは交代しない
- 蟻 … 全部の蟻が動く。自分から一番近い荷物を、歩いてきた向きのまま押す。
  押せないときは動かない。左上に近い蟻から順に、前の蟻が動いた結果を見て動く

蟻の細かい順序（こちらで決めたもの。違ったら直す）:
歩いた距離が短い順 → 上・下・左・右の順 → 盤の左上に近い荷物。

## 6. この環境の落とし穴（何度も踏んだ）

- **作業ディレクトリが何度も古いコミットまで巻き戻る。** コミットしていない変更は消える。
  このセッション中に4回起きた。**作業は小さく切って、その都度コミットしてプッシュすること。**
  戻ったら復帰は
  `git fetch origin <branch> && git checkout -B <branch> origin/<branch>`
- **`/tmp` も消える。** 時間のかかる計算の控えは `tools/stock/` に置く
- **同時に何本も走らせるときは、控えを担当ごとに別ファイルにする。**
  1つのファイルを読んで書き足す形だと、後から書いたほうが前のを丸ごと消す（132面ぶん消えた）
- **`pkill -f "..."` は自分の shell も殺す。** パターンが自分のコマンド行に一致するため。
  PID を調べて `kill <PID>` にするか、`pkill -f "^node --max-old-space-size"` のように
  自分に当たらない形にする
- CSS の `rotate` プロパティは `transform` より**先に**掛かる。同じ要素で両方を使うと
  移動の向きまで回ってしまう（ころがしで実際に起きた。移動は `left/top` に分けてある）
- `left` を空文字に戻すと `auto` になり、`auto` とは繋がらないので飛ぶ。`0px` を書くこと
